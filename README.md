# ww-echo

基于图像识别的鸣潮声骸强化自动化工具。从 [ok-ww](https://github.com/ok-oldking/ok-wuthering-waves) 剥离声骸模块，基于 [ok-script](https://github.com/ok-oldking/ok-script) 的截图/OCR/键鼠能力，自建 PySide6 管理界面。

*An image-recognition-based Wuthering Waves echo enhancement tool with custom PySide6 UI.*

*通过 Windows 接口模拟用户操作，无内存读取、无文件修改*

## 功能 | Features

### 强化声骸 | Enhancement

自动将背包中的 0 级声骸强化至满级并调谐，按规则判断保留或丢弃。

- **渐进式**: 每级单独评估，不达标立即丢弃止损
- **传统**: 拉满后一次性判断
- **均值归一化评分**: 单词条=档位值÷均值×权重，带权重的词条当量评分
- **套装模板**: 34 个套装独立配置预期词条和权重，JSON 文件即保存即导入

### 评估声骸 | Evaluate

只读模式，**自动遍历整个背包**(每行6格网格) 截图+打分，生成 **HTML 报告**。

- 自动遍历: 点格 → 读右侧详情 → 按词条档位精确识别 → 评分 → 6 列补全防漏 → 自动下滑 → 左上数量上限/到底自动停止
- 词条过滤: 主属性/非词条数值(攻击150、生命1915、54 等) 自动剔除, 仅保留落在词条档位集合上的真词条(≤5条)
- 每个声骸: 截图 + 名称 + **套装**(鼠标悬停看来源: 套装图标判定 / 声骸名兜底 / 通用) + 得分 + 判定（达标 / 待强化 / 建议保留重铸 / 不合格）
- **套装自动判定**: 优先读详情面板的**套装图标**(模板匹配 34 套), 名字多义/OCR 错字(如 `梦魔·青羽鹭` 实为 `梦魇·青羽鹭`)时**以图标为准**; 图标不可用则回退"按声骸名映射套装"(每套装可配声骸清单 4C/3C/1C), 仍未录入则用通用权重
- 报告可筛选: 得分区间(≥/≤)、判定多选、名称包含匹配、**套装**(下拉, 带条目数); 词条按档位单色相渐变着色(蓝色系, 越深越高档)
- 输出 `eval_report.html` + 截图文件夹，双击浏览器查看
- 不强化、不上锁、不丢弃 — 纯评估

### 云游戏 / 本地双模式 | Local / Cloud

在"设备设置"顶部切换运行模式（重启生效）：

- **本地客户端**(默认): 自动匹配 `UnrealWindow` 游戏窗口, 支持后台运行
- **云游戏**: 自动锁定标题含"鸣潮"的浏览器/云客户端窗口(无需手动选窗), 前台真实键鼠操作
  - 用法: 云游戏页面 **F11 全屏**保持前台可见 → 启动程序自动连接 → 点"开始"(程序自动切前台) → 任务运行中勿最小化游戏
  - 需以**管理员身份**运行(前台键鼠注入)

## 强化策略 | Enhancement Strategies

### 渐进式 (默认) | Progressive

| 阶段 | 条件 | 不达标处理 |
|:--:|------|------|
| Lv5 | 首条为有效词条(不限分) | 丢弃 |
| Lv10 | 跳过 | — |
| Lv15 | 累积得分 ≥ 20 | 丢弃 |
| Lv20 | 累积得分 ≥ 26 | 丢弃 |
| Lv25 | 累积得分 ≥ 32 | 丢弃；达标上锁 |

未满级声骸: 先读已有词条做渐进判断，通过再继续强化。

### 传统 | Traditional

满级后一次性判断: 必须有双爆 / 首条阈值 / 双爆总计 / 有效词条数量 / 首条必须有效 / 可选评分。

## 评分系统 | Scoring

**均值归一化 ×10 + 权重**: 单词条 = `档位值 ÷ 该词条均值 × 10 × 权重`(上限自然 12.5/条)，无效词条 = 0 分。

```
暴击均值 8.4%, 权重 1.0:
  最低 6.3% → 6.3/8.4×10×1.0 = 7.50
  最高 10.5% → 10.5/8.4×10×1.0 = 12.50

通用默认权重: 暴击 1.0  爆伤 0.9  攻击% 0.85  共效 0.7
              专伤(普攻/重击/共技/共解) 0.6  生命%/防御% 0.85
              固定攻/生命/防御 0.5 (白值700-1000下小攻击≈1%攻, 全乘区通用)

达标线(锚线): = 本只"出现的有效词条"的"平均档加权分"(10×权重)平均值 × (词条数-1)
      "有效" = 该套装启用了的词条(权重>0); 出现有效词条 0 条 → 回退通用 11 / 18 / 26.5
      下限 = max(套装有效键最低 L 条之和, 通用代表集最低 L 条之和=11/18/26.5) → 保证不比通用标准松,
      也避免"有效词条少且权重低"时算出 4.0 这类漏网的线
      通用与套装同此算法 —— 旧"取套装最低 L 条之和"单独使用已废弃: 键多但权重低的套装会被低估到
      5~6 分, 反而"词条种类越多越容易达标"。(通用角色适配集6种: 暴/爆/攻%/共效/一种专伤/固定攻)
      判定(五档, 满级): A ≥ B 且 score ≥ A → 达标 / score ≥ B → 保留
                       (A < B 时最高只能到"保留": 出现有效词条太少, 达标线不成立)
                       胚子信号(≥2条达平均档 或 四有效打底) → 建议重铸 / 否则 → 不合格
      未满级: score ≥ B → 待强化; 否则不合格。(A=达标线, B=旧规则线, 见上)
套装模式: 权重取套装模板(与通用同尺度≤1, 词条选择按套装)
```
