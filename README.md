# ww-echo

基于图像识别的鸣潮声骸强化自动化工具。从 [ok-ww](https://github.com/ok-oldking/ok-wuthering-waves) 剥离声骸模块，基于 [ok-script](https://github.com/ok-oldking/ok-script) 的截图/OCR/键鼠能力，自建 PySide6 管理界面。

*An image-recognition-based Wuthering Waves echo enhancement tool with custom PySide6 UI.*

*通过 Windows 接口模拟用户操作，无内存读取、无文件修改*

## 功能 | Features

### 强化声骸 | Enhancement

自动将背包中的 0 级声骸强化至满级并调谐，按规则判断保留或丢弃。

- **渐进式**: 每级单独评估，不达标立即丢弃止损
- **传统**: 拉满后一次性判断
- **期望归一化评分**: 单词条=档位值÷期望值×权重（期望 = 官方公示的概率期望档位值），带权重的词条当量评分
- **套装模板**: 37 个套装独立配置预期词条和权重，JSON 文件即保存即导入

### 评估声骸 | Evaluate

只读模式，**自动遍历整个背包**(每行6格网格) 截图+打分，生成 **HTML 报告**。

- 自动遍历: 点格 → 读右侧详情 → 按词条档位精确识别 → 评分 → 6 列补全防漏 → 自动下滑 → 左上数量上限/到底自动停止
- 词条过滤: 主属性/非词条数值(攻击150、生命1915、54 等) 自动剔除, 仅保留落在词条档位集合上的真词条(≤5条)
- 每个声骸: 截图 + 名称 + **套装**(悬停看来源: 套装图标判定 / 声骸名兜底 / 通用) + **COST/主属性**(含官方方案判定) + 得分（下方标 **完成度 X%**）+ 判定（达标 / 保留 / 建议重铸 / 建议强化 / 不建议强化）
- **套装自动判定**: 优先读详情面板的**套装图标**(模板自动匹配 37 张官方贴图), 名字多义/OCR 错字(如 `梦魔·青羽鹭` 实为 `梦魇·青羽鹭`)时**以图标为准**; 图标不可用则回退"按声骸名映射套装"(官方配置表 **229 个显示名 / 37 套**, `异相·X` 皮肤条目按自己的套装), 仍未录入则用通用权重
- **COST 与官方主属性方案**: 报告「COST/主属性」列给出 COST 角标(1/3/4)、两条主属性, 以及游戏内置**声骸管理方案**(每套装 × COST 的保留/丢弃主属性组)判定: `✔` 官方保留 / `✘` 官方丢弃 / `·` 官方未表态
- 报告可筛选: 得分区间(≥/≤)、判定多选、名称包含匹配、**套装**(下拉, 带条目数); 词条按档位单色相渐变着色(蓝色系, 越深越高档), 每条尾附**分位 `[前 X%]`**（官方档位概率不等，同一个"档位水平"在各词条上稀缺度不同，分位才跨词条可比）
- 输出 `eval_report.html` + 截图文件夹，双击浏览器查看
- 不强化、不上锁、不丢弃 — 纯评估

### 云游戏 / 本地双模式 | Local / Cloud

在"设备设置"顶部切换运行模式（重启生效）：

- **本地客户端**(默认): 自动匹配 `UnrealWindow` 游戏窗口, 支持后台运行
- **云游戏**: 自动锁定标题含"鸣潮"的浏览器/云客户端窗口(无需手动选窗), 前台真实键鼠操作
  - 用法: 云游戏页面 **F11 全屏**保持前台可见 → 启动程序自动连接 → 点"开始"(程序自动切前台) → 任务运行中勿最小化游戏
  - 需以**管理员身份**运行(前台键鼠注入)

## 强化策略 | Enhancement Strategies

### 渐进式 (默认) | Progressive

| 阶段 | 条件 | 不达标处理 |
|:--:|------|------|
| Lv5 | 存在首核词条(不限分) | 丢弃 |
| Lv10 | 存在首核词条(不限分) | 丢弃 |
| Lv15 | 总分 ≥ 基准线 B, 或 前瞻概率 ≥ 60% 且 总分 ≥ 达标线 A | 丢弃 |
| Lv20 | 同 Lv15 | 丢弃 |
| Lv25 | A ≥ B 且 总分 ≥ A(达标) | 丢弃；达标上锁 |

两线口径(与评估共用 `judge_echo`): **达标线 A = 10 × 本只出现的有效词条权重和**;
**基准线 B = 该套装有效键最低 (n−1) 条之和 ×10**（未定制配置的套装 = 通用线 **6.5 / 11.5 / 17.5**）。
满级未过基准线时还会看"锁 N 条刷 M 条后达标概率 ≥ 60%"→ 建议重铸（细节见 `eval_rules.md`）。

未满级声骸: 先读已有词条做渐进判断，通过再继续强化。

### 传统 | Traditional

满级后一次性判断: 必须有双爆 / 首条阈值 / 双爆总计 / 有效词条数量 / 首条必须有效 / 可选评分。

## 评分系统 | Scoring

**期望归一化 ×10 + 权重**: 单词条 = `档位值 ÷ 该词条期望值 × 10 × 权重`，无效词条 = 0 分。
"期望值" = 官方公示的**概率期望档位值**（Σ 档位值×概率，见 `assets/echo_probability.json`；**展示与计算统一保留 1 位小数**），
不是算术平均——官方档位概率并不相等（暴击最低三档各 23.3333%、最高档仅 3%），期望比算术平均低约 10%（双暴）/ 2%~3%（其余）。
所以**平均档 = 10.0 分，满档 ≈ 13.1~14.0 分**（按算术平均归一化时上限才是 12.5）。

```
暴击期望 7.5%, 权重 1.0:
  最低 6.3% → 6.3/7.5×10×1.0 = 8.40
  最高 10.5% → 10.5/7.5×10×1.0 = 14.00

通用默认权重(阶段十八: 按满档词条的**边际收益**重排, 旧值见 CHANGELOG):
              暴击 1.0   爆伤 0.7   攻击%/生命%/防御% 0.5   共效 0.6
              专伤(普攻/重击/共技/共解) 0.4   固定攻/生命/防御 0.25
              依据: 覆盖**普通链度/命座**的面板(c≈70% / 爆伤≈200%) —— 爆伤的相对价值 = 2c/d,
              随练度提高而回落(c70/d200 → 0.70, c90/d300 → 0.60), 故取 0.7;
              大攻被套装与辅助放大到 0.5; 共效循环刚需但够用即溢出 → 0.6, 由套装按角色调整;
              专伤比大攻更小且增伤区易稀释 → 0.4; 小值恒为大值的 0.5 倍

达标线 A = 10 × 本只"出现的有效词条"的权重之和
      "有效" = 该套装启用了的词条(权重>0); 出现有效词条 0 条 → A = 0(该只不可能达标)
基准线 B = 该套装有效键权重升序最低 (词条数-1) 条之和 × 10
      未定制配置的套装其 B 即通用线: Lv15 / Lv20 / Lv25 = 6.5 / 11.5 / 17.5
      (旧"用最低 L 条之和当达标线"已废弃 —— 键多但权重低的套装会被低估到 4~6 分,
       反而"词条种类越多越容易达标"; 但它仍作为**基准门槛**保留)
判定(满级): A ≥ B 且 score ≥ A → 达标 / score ≥ B → 保留
           否则 穷举"锁 L 条 + 刷 5−L 条"、取成本最低的方案, 要求**蒙特卡洛达标概率 ≥ 0.60** → 建议重铸
           都不满足 → 不合格    (A < B 时最高只能到"保留": 出现有效词条太少, 达标线不成立)
判定(未满级): score ≥ B(满级) → 建议强化
            否则 前瞻概率(继续开到满级能过 B 的概率) ≥ 0.60 且 score ≥ A(现有) → 建议强化
            否则 → 不建议强化
      依据: **胚子可无限刷, 而强化材料/频整器有限** → 不为低概率花资源
套装模式: 权重取套装模板(词条选择与组内比例按套装; 权重整体缩放不影响判定)
```
