## 2. 遍历：54 → 113 → 115 → 155 的四轮

每一轮都从日志取证，逐条修：

### 2.1 54 条（`f336018`）
- 日志：`滚轮: 40 格 → +0.5 行 (≈4.8px/格, 残差 32)` → 8 格无变化 → `滚动受阻` → 中止。
- 根因：0.6s 单次采样落在动画中途；`estimate_row_shift` 搜索范围只到 4 行（5~6 行时返回 0）；
  三种输入连发叠到 6 行；列拟合用端点法被"贴边截断的金条"带偏（列距 107 vs 113）。
- 修：测到停稳（`frame_change_ratio`）、范围放宽到 `(视口高-20)/行距`、一次一种输入 + 残余闭环、
  `fit_lattice`（相位法+最小二乘+补漏列）。

### 2.2 113 条（`0535f22`）
- 日志：`+0.2 行, 停稳 0.52s` + 第 3/4 屏 `重复 0`（滚过头、整行被跳）。
- 根因：滚动是 **ease-in**，前 0.5s 只走 0.2 行；"两次读数一致即停稳"在慢启动阶段就满足。
- 修：`_wait_still` 改成看**相邻两帧的差异**（与位移读数无关）；`observe()` weight=1.0；发送距离打 0.95 折。

### 2.3 115 条（`b23115c`）
- 把数算通：**64 格 → 约 4 行 = 552px ⇒ 8.6 px/格**，而模型以为 5.2（按帧宽缩放）→ 每次请求 2.5 行实际走 4~5 行。
- 修：px/格 **固定 8.0 不随帧宽缩放**；目标 3 行；**无重叠守卫**（非首屏 `重复/点空==0` → 回滚 1 行重扫）。
  这一版真机跑到 **155** 条（日志里能看到守卫触发并自愈）。

### 2.4 1440x900 的收尾（`8848ec7`）
- `本屏网格: 6 列 × 4 行` → 目标行数随可见行数收缩（`min(3, 可见-1.8)`），4 行时降到 2.2。

> **仍然测不准**：真机上 `estimate_row_shift` 残差常年 25~34（画面完整度/动画帧），
> 所以整条链**不依赖像素位移**，只把它当"动没动"的证据；距离靠固定 px/格 + 无重叠守卫兜底。

## 3. 套装：四次重构，最后落到"读文字"

| 阶段 | 提交 | 结论 |
|---|---|---|
| 面板图标（旧方案） | — | 3.x UI 起 `ICON_BOX` 落在绿色「+」按钮上，155 条 icon 命中 **0** |
| 卡片徽章环色 | `7ff3113` | 28px 徽章与模板**不是同一套图**（灰度 ZNCC 0.2~0.3、二值形状 IoU ~0.2）；**环色**可分 8 组，158 个多义名里 85% 可唯一定位 |
| 合鸣效果文本反查 | `ad33d29` | `match_set_effect`：37 套 2/5 件效果原文，字符二元组覆盖率 + 候选约束；离线 0.73 vs 0.14 |
| **合鸣效果区的套装名** | `6c83890`/`d6b8028`/`83a32f5` | 面板底部每条效果都写套装名 → `match_set_text` 直接读；用户三张截图离线回放：**conf 1.00 命中** |

**当前判定顺序**（`resolve_set_name`）：
```
合鸣效果区的套装名明文(match_set_text)
  → 合鸣效果原文覆盖率(match_set_effect)
  → 详情面板图标(旧 UI)
  → 卡片徽章环色(85%)
  → 名字候选 → 通用
```
`set_src` = `text` / `effect` / `icon` / `hue` / `name` / `default`，每条评估日志都带。

**找套装的滚动策略**（`read_set_by_effect`）：
- 第一步 12 格（主词条区肯定没有套装名），之后每步 **6 格**，最多 9 步（60 格）；
- 每步 OCR **整块面板**（`_effect_box`），命中即停：套装名（**独占一行**才算）/ 效果覆盖率 / 已见「合鸣效果」标题再滚 2 步 / 面板到底；
- 读不到候选（名字 OCR 错字）时**放开到 37 套**再认一次；读完按实际格数滚回顶部并校验名字行。
