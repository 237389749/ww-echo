## 2. 时间线：每一修都从"证据"出发

### 2.1 分辨率：`ratio` 不是校验开关，是坐标映射

- **现象**：1024x768 窗口下点选纵向偏，点到上一行。
- **证据**：`BaseTask.out_of_ratio()` 为真时，`box_of_screen`/`click_relative` 按 `should_width = ratio × height`
  居中映射；1254x889 实测相对 y=0.381 → 269px，正确应为 338px，**偏上 69px ≈ 半行**。
- **修复**：两种运行模式都 `supported_resolution['ratio']=None`，按帧宽高**线性**映射；`min_size=(800,600)`。
- **验证**：`tests/test_run_modes.py` 2 项（本地/云 ratio=None、min_size ≤1024x768）。
- **提交**：`6307144`。

### 2.2 三处遍历 bug（首屏 13 条、重复行、首格是旧选中）

- **现象**：报告 13 行，其中 #5/#11/#12 全同、#7/#13 全同；#1 是之前手选的那只。
- **三个根因**：
  1. **角标召回低**：`+25` 只有 10~14px 高，OCR 单次只检出 5~14/30，还会拆成 `+` / `25` → 漏格、点隔壁；
  2. **滚轮坐标空间错**：`WM_MOUSEWHEEL` 的 lParam 是**屏幕坐标**（其它鼠标消息才是客户区），旧实现塞客户区 → 列表根本不滚；
  3. **陈旧面板当首条**：第一次点击没切换时，详情还是上一次选中的声骸。
- **修复**：①两路 OCR 并集 + `merge_badge_marks`（拆框合并/去重/ROI）+ `cells_from_marks`；②滚轮改屏幕坐标；
  ③进循环前先读一次详情做基线，每格点不中就向格子中心偏一点重试一次，另用**属性行签名**（不含名字）防重复。
- **验证**：`tests/test_grid_scan.py` 15 项（合并/ROI/6×5 还原/单行行距）。
- **提交**：`c0d9efc`。

### 2.3 网格标定：放弃识别文字，改用"结构线"

- **思路**：网格的**等级条**是天然结构：每格一条，条顶边是一条强横边；条的亮段是金色。
- **算法**（`src/echo_grid.py`）：
  - 行：Sobel-y 投影 → 自相关估行距 → 等间距格点拟合，要求落在强横边上；
  - 列：HSV 金色掩膜 → 每行取 6 段 → 段中心聚类，只收 ≥2 行支持的列。
- **实测（两张真实帧）**：行 `[184,322,460,598,736]`、列 `[163,278,393.5,508.5,623.5,739]`，
  两帧差 ≤0.1px，**6×5=30 格**，纯投影 ~10ms/屏（OCR 并集 ~0.8s/屏）。
- **失败回退**：检测不到（例如整屏 0 级、金线不明显）才走角标 OCR 并集。
- **验证**：3 项合成帧（6×5 / 空帧 None / 点击点偏移）。
- **提交**：`c0eb981`。

### 2.4 布局模型：把"比例"抽象出来，跨屏复用

- **观察**：网格几何只随**帧宽**缩放（列距 0.0917×W、行距 0.110×W；1920→176/212，1254→115/138），
  与帧高/DPI 无关。
- **做法**：首屏完整标定后存 `GridModel`（列距/行距/首列比例），后续屏幕只做 Sobel 行检测（~10ms）+ 模型给列；
  行距变化 >12% 判模型失效 → 重新完整标定 → 再失败才 OCR。
- **验证**：4 项（复现、matches、滚动位移、模型给列）。
- **提交**：`6faf68a`。
- **附带**：`tools/analysis/probe_keyboard_nav.py` 键盘遍历探针（`ffac108`，**尚未跑**）。

### 2.5 停止按钮：协作取消，而不是 `disable()`

- **现象**：点停止后 UI 显示已停止，后台仍点击/OCR/滚屏。
- **根因**：评估跑在 `ui/run_tab` 自己的线程里，`task.disable()`/`unpause()` 只对 executor 线程生效。
- **修复**：`threading.Event` + `request_stop()/stop_requested()/reset_stop()`；`evaluate_only` **每屏/每格**检查；
  停止后**不生成报告、不回调 `on_done`**，删临时目录，日志记已处理数量；UI 启动前 `reset_stop()` 防"开始即停止"被清。
- **验证**：`tests/test_eval_stop.py` 2 项静态接线守卫；全量 205 项。
- **提交**：`031a1ff`。

### 2.6 去掉"声骸 N/3000"：直接遍历，0 级尾部停

- **证据**：数量 OCR 每屏一次，且 N 可能是总数/滚动位置，语义不清；锚点失败还会污染"首屏空网格"的报错。
- **修复**：删除 `read_count`/`count_box`/页面锚点/`total_limit`/`handled`；新增 `zero_run` + `ZERO_TAIL_STOP=12`
  （连续 **12 格** 0 词条 = 两整行 → 视为 0 级尾部）；保留"网格连续 2 次为空"兜底与首屏空网格报错。
- **取舍**：未按等级排序时，连续 12 个 0 词条可能出现在中部 → 会提前两行结束；可调阈值。
- **验证**：`tests/test_eval_traverse.py` 3 项（无 count OCR / 有尾部早停 / 无锚点提示）；全量 211 项。
- **提交**：`429c0c3`。

### 2.7 滚动的四次修正（本次最费时的一段）

| 轮次 | 改动 | 真机结果 | 教训 |
|---|---|---|---|
| 1 | `WM_MOUSEWHEEL` lParam 改**屏幕坐标**，逐格发 `WHEEL_DELTA` | 仍不滚（29 条 = 首屏 30 格） | 坐标对了不等于游戏认 |
| 2 | 校验"行线有没有变"（`rows_differ`），无效切**真实滚轮**（`bring_to_front`+`SetCursorPos`+Pynput） | 53 条：第一次滚了约 4 行，后 3 次完全没动；**日志里没有滚轮信息** | 校验误判 → 真实兜底**从未触发**：行检测偶尔多/少一行（759px 的条底边）就判"变了" |
| 3 | 改**位移测量** `estimate_row_shift`（按行距搜整数行 + ±半行内 4px 细化） | 离线：60/120/200/276/414/552px → 0.43/0.88/1.46/2.00/3.00/4.00 行 | 距离可测，但仍是"滚完再看" |
| 4 | **`ScrollModel`**：距离 = 行数×行距 ÷ 实测 px 每格；每次滚动 `observe()` 校正；失败三重兜底 + 连续 2 次失败即中止 | **待真机复跑** | 距离与失败都要"有界、可解释" |

- **为什么真实滚轮无效兜底当初没触发**：`rows_differ` 比较"行线列表"，行数 5↔6 或位置抖动 >4px 就返回"变了"；
  行检测本身会偶发把 759px 的条底边当成行线。**改用像素位移测量**后该问题消失（`rows_differ` 已删除）。
- **为什么是 4 行**：可见 5 行，留 1 行重叠 → 距离误差 ±1 行也不会出现空洞；重叠由 `dedup_key` 吸收。
- **受阻不空转**：`scroll_grid()` 返回 False 时依次试 真实滚轮 → PostMessage → 拖拽；连续 2 次 False →
  `滚动受阻…已记录 N 条, 生成部分报告` 并结束（旧逻辑要空转 3 屏 ≈30 秒）。
- **提交**：`37aa0e1`（真实滚轮兜底）、`129f9ea`（位移测量）、`405a280`（ScrollModel + 有界终止）。

第二屏 = 6 重复 + 24 新，说明**第一次滚动其实滚对了 4 行**（只是量成了 0.5）。后面两次"受阻"才是真问题。

**四层根因**（都能离线复现）：
1. **测量时机**：滚动是**动画**，固定 `sleep(0.6)` 单次采样落在动画中途 → 量到 +0.5 行（实际 4 行）。

   兜底滚屏走 5~6 行时估不出来，**返回 0.0**（用真帧模拟 5 行位移 → 返回 0.0、残差 5.7）→ 被当成"受阻"。
3. **输入叠加**：旧 `scroll_grid` 把「真实滚轮 → PostMessage → 拖拽」**连发**，三次叠起来能滚 6 行 > 可见 5 行

4. **列拟合用端点**：真机 7 列帧里第一根金条被 ROI 截断（段 `(94,115)`，中心 104.5，真值 70.5），

**改动**（`src/echo_grid.py` / `src/task/EnhanceEchoTask.py`）：

| 问题 | 改动 | 离线证据 |
|---|---|---|
| 采样在动画中途 | `_measure_shift`：0.15s 轮询，**连续两次读数一致 + 画面确实变了**才收工 | 真帧：滚完到停稳 0.4~1.0s |

## 3. 抽象出的四层模型

```
帧像素(1254x889 或任意)
   │  归一化坐标 (0~1)
   ▼
结构线检测  echo_grid.detect_grid_structure / detect_row_lines
   │  rows(条顶边) + cols(金线亮段)
   ▼
GridModel   列距/行距/首列 比例（只随帧宽）
   │  cells(nx, ny) + row_pitch_px
   ▼
ScrollModel 目标行数×行距 ÷ px每格 → notches
   │  observe(实测行数) 校正
   ▼
失败策略     三重兜底 + 连续 2 次失败 → 部分报告
```

**要点**：上层只依赖"比例/像素"这类可测量，不依赖分辨率常量；任何一层失效都有下一层兜底，
且**失败次数有界**。

## 4. 可复用的设计原则

1. **测量代替猜测**：滚动距离、位移、点击是否生效，都要有可验证的观测量（行位移、详情签名），
   不要靠"应该可以"。
2. **结构优先，文本兜底**：能靠几何结构（条顶边、金线、行距）解决的，不要依赖 OCR 角标/计数。
3. **距离有界 + 失败有界**：目标位移固定（4 行），偏离可测可调；失败重试有限次，超限就带警告中止并保留部分结果。
4. **状态机式终止**：出口互斥且可解释 —— ①0 级尾部（12 格 0 词条）②列表底（网格连续为空）③滚动受阻（部分报告）
   ④用户停止（不生成报告）。**不允许"无出口循环"**。
5. **调用面不变**：`evaluate_only`/`evaluate_one`/UI 回调签名都没动，改动集中在实现内部与新增纯函数模块。

## 9. 术语

| 术语 | 含义 |
|---|---|
| `ratio` | 坐标映射的**参考比例**（不是校验开关）；`None` = 按帧宽高线性映射 |
| `GridModel` | 网格几何比例（列距/行距/首列），首屏标定后跨屏复用 |
| `ScrollModel` | 滚动换算（行数×行距 ÷ px 每格），实测校正 |
| 0 级尾部 | 按等级排序时列表末尾的 0 词条声骸；连续 12 格即判定 |
| 受阻 | 三种滚动方式都测到位移 <0.35 行 |
