## 3. 关键决定（本会话已定）

1. **通用共效 0.6→0.5**：依据参考工程 linear 爱弥斯 0.40、Wuwa 中位 0.35；用户拍板 **0.5**，不是 0.4~0.45。
2. **通用 B 仍固定 17.5**：`_GENERAL_WEIGHTS` 改为固定策略档位 `(1.0,0.7,0.6,0.5,0.4,0.25)`。
   若继续用 `DEFAULT_WEIGHTS` 去重自动推导，0.5 与攻击%合并后档位变少，B(5) 会从 17.5 抬到 18.5
   （等于顺手收紧保留线）；这不作为权重调整的副作用。以后要改 B 需显式决定。
3. **不引入 Rust**：参考项目的 Rust 核心是精确策略 DP/服务端/Tauri；我们当前瓶颈是 OCR/游戏 IO，
   `reforge_plan` 仅 ~190ms，numpy 向量化就够；Rust 只在将来做“期望成本 DP”时作为可选求解器后端。
4. **不修改强化/重铸阈值、不引入主属性进评分**：P1（强化 0.60 门槛拆分）与 P2（主属性）仍需用户拍板。
5. **`og`/`communicate` 保留**：它们是运行时服务定位，不是 import 环；domain 已不碰 `og`。
6. **P1 只搬实现、不改口径**：`EnhanceEchoTask` 保留同名薄封装（线上评估/离线重放/测试的调用面不变），
   `set_name=None → config['当前套装']` 这种“任务运行时默认值”留在 adapter；等价性用 `p1_equiv_check.py` 钉住。
   任务 `icon/group_icon` 置 `None` 的依据：本项目自建 Fluent UI 不渲染任务图标（全仓无消费者），
   换来 task adapter 完全不 import `qfluentwidgets`。
7. **P2 只做“根包惰性 + 去 FluentIcon”，不动行为**：`_LAZY_IMPORTS` 覆盖原来顶部 import 的 12 个名字，
   其余（`og`/`Logger`/`Config`/`Handler`/`communicate`/异常/文件工具）保持 eager；`OK` 内改函数内 import。
   **`communicate` 保持 eager**：它是 `Signal` 中心，任何 UI/引擎消费方都要 QtCore（≈131 ms），
   惰性化只对“连 Qt 都不装的脚本”有意义，而那些脚本（如 `echo_plan`）现在根本不 import `ww_engine`。
   守卫用**子进程实测**（静态扫描看不出“函数内 import 也是合法写法”），见 `tests/test_engine_lazy.py`。
8. **第三阶段只拆“外壳”，`communicate` 留在 engine**：它被 7 个 engine 核心模块直接 emit，搬走会让
   engine→shell 变成到处都有的边；它是“engine ↔ UI 的契约面”，单点 QtCore 依赖是刻意的。
   `og` 改名目录 `locator`（**不能叫 `globals.py`**：子模块会成为父包属性并遮蔽内置 `globals()`，实测报
   `TypeError: 'module' object is not callable`）；组合根保留 `EngineApp` 惰性导出，`from ww_engine import OK` 不变。
   同轮修了体检工具的 `from . import X` 假边（此前所有 SCC 数字偏大），并补回矩阵的 engine 列。

**定位到 3 个问题（互相叠加）**

| # | 现象 | 根因 |
|---|---|---|
| 1 | 第一格不是第一格、漏列/点错格 | 小窗口 `+25` 只有 10~14px 高，OCR **单次只检出 5~14/30**，还会把 `+25` 拆成 `+`+`25`；旧 `scan_grid` 只按单次结果聚行聚列 → 缺行缺列 |
| 2 | 13 条之后空转、列表不滚、重复记录 | 本地 `PostMessage` 滚轮把**客户区坐标**塞进 `WM_MOUSEWHEEL`（该消息 lParam 要求**屏幕坐标**）→ 游戏忽略滚轮，每屏重复扫同一批格子；最后触发"连续滚动无进展" |
| 3 | `#1` 是陈旧声骸 | 第一次点击未生效时 `read_detail` 读到的是**上一次选中的面板**（用户手选的「海维夏」），被当成本屏第一只记录 |

**修复**

- 新增 `src/echo_grid.py`（纯几何, 可单测）：`merge_badge_marks`（合并 `+`/`25` 拆框、两路 OCR 去重、ROI 挡掉详情面板自己的 `+25`）、
  `cluster_axis`/`infer_axis_centers`（等间距补全缺列/缺行，范围限制在网格区，不碰表头/底部按钮；缺间距沿用上一屏）、`cells_from_marks`。

- `evaluate_only`：进循环前先读一次详情面板做基线；每格点击后签名未变（或没读到属性）就**向格子中心偏一点重试一次**，仍不变则跳过；

## 6.8 换标定物：用网格结构线代替 +25（2026-11-14 13:00~13:20，离线验证）

用户判断「靠角标识别暴露的问题太大，能否换标定物」。结论：**能，且不需要识别任何文字**。

**做法**（`src/echo_grid.detect_grid_structure` / `cells_from_structure`）
- **行** = 每格底部**等级条的顶边**：Sobel-y 投影 → 自相关估行距 → 等间距格点拟合；拟合点必须落在强横边（>2×均值）上，否则判失败。
- **列** = 等级条顶边的**金色亮段**：HSV 金色掩膜 → 每行约 6 段（宽 ~90px）→ 段中心聚类（只收 ≥2 行支持的列）→ 6 列（≈格中心）。
- 点击点 = (列中心, 行线 + 0.08×行距)；失败回退「角标 OCR 两路并集 + 推断」（保留）。

**实测（两张不同时间的真实帧 1254x889）**

| 项 | 结果 |
|---|---|
| 行线 | `[184,322,460,598,736]`，两帧完全一致；行距 **138px** |
| 列中心 | `[163,278,393.5,508.5,623.5,739]`，两帧差 ≤0.1px；列距 **115px** |
| 网格 | **6×5 = 30**，第一格 (163, 195) |
| 与旧点击点 | 旧角标中心 `[191,306,422,537,650,768]`；新点左移 ~29px（仍在格内且更居中） |

**取舍**
- 优点：完全不做文字识别（不受 `+25` 小字漏检影响）；滚动后相位自动重算；间距按像素估，分辨率/DPI 无关；~10ms/屏（OCR 并集 ~0.8s/屏）。
- 风险：依赖「等级条存在且带金色顶边」——0 级（`+0`）条颜色可能不同，整屏全 0 级时可能失败 → 自动回退 OCR；UI 大改需复核 ROI（0.075–0.655W / 0.10–0.90H）。

**验证**：`tests/test_grid_scan.py` 新增 3 项合成帧测试（检测 6×5 / 空帧返回 None / 点击点偏移）；全量 **199 项 OK (skipped=2)**。

**顺带（未做，等真机）**：键盘遍历探针 `tools/analysis/probe_keyboard_nav.py` 已在仓库里，方向键若可用则可再升级为「零坐标遍历」；
本节的「结构线标定」是**不依赖键盘**的那条路线，二者不冲突（结构线仍能给出首格位置）。
