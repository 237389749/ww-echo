## 2. 滚动：三件事一起改

### 2.1 px/格 必须标定（不能写死 8）

- 证据：首滚 42 格（按 8px/格 以为 2.2 行）→ 下一屏 **0 格重复**（可见 4 行全翻过去）→ 反推 ≈19.7 未标定前实测 ≈15
- 做法：`scroll_grid` 第一次只发 **6 格**（位移 <1 个行距），用 `echo_grid.row_shift_by_lines` 量出行数，
  反推 px/格，再滚剩下的；失败就保留默认值（宁可欠滚）。

### 2.2 之后每次滚动也用行线量

- `_measure_shift` 优先 `row_shift_by_lines(..., expect_rows=发了几格×当前px/格/pitch)`，
  **±0.45 行窗口**避开行线周期歧义；只有行线不可信（中位误差 >6px）才退回图像相关。
- 这样 `observe()` 才有真数据：日志从"残差 27~34 / +0.2 行"变成"残差 0 / +1.7 行"。

### 2.3 滚动量按"页"算（用户口径）

- 一页 = **本屏检测到的行数 × 行距**（4/5 行随分辨率变，6 列是常量）；
  每次滚 **`SCROLL_PAGE_FRACTION = 0.6`（一页的 60%）**，并留 ≤ 行数−1，保证页内至少 1 行重叠。
- 日志：`滚动规划: 本屏 4 行 × 159px = 一页 636px, 目标 2.4 行(60% 页)`。

## 4. 主属性百分比变体（本轮最隐蔽的 bug）

```
normalize_main_prop("攻击", "30.0%") -> "攻击百分比"
value_grid("攻击百分比")             -> []        ← 生成物里 key 是 `攻击`（固定/百分比两变体）
_main_props_like                     -> False     ← 3C 的 攻击% 主属性永远"不像"
_parse_stats                         -> []        ← 整只被当"0 级/读失败"丢掉
```

- 影响面：**所有主属性是 攻击% / 生命% / 防御%** 的声骸（3C 的攻击%/生命%，1C 的生命%/防御%…）。
  以前报告里"莫名少掉的件"应该有一批是这个 —— 不是没扫到，是扫到了被吞了。
- 修法：`src/echo_main_prop._candidates` 认 `X百分比` → 回落基名 `X` 且只取 `pct=True` 的变体。
- 单测：`TestPercentVariantGrid`（网格含 30.0、不含 100；`_main_props_like` 为真；其后词条照常解析）。
